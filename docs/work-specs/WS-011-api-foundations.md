## Approach

Four small pieces. None of them touches the database.

1. **Problem schema** (`src/lib/schemas/problem.ts`). `problemSchema` is the Zod object of
   doc 0004 section 4 (`type`, `title`, `status`, `code`, `detail`, `requestId`, optional
   `errors`). `problemCodeSchema` is the enum of base codes. It lives in `lib/schemas`
   because the UI will parse error bodies with it too.

2. **API errors** (`src/server/http/errors.ts`). `ApiError` is an `Error` subclass
   carrying `status`, `code`, `detail` and optional `errors`. Named constructors cover
   the base codes: `invalidRequest(errors)`, `unauthenticated()`, `forbidden()`,
   `notFound()`, `conflict(detail)`, `unsupportedMediaType()`, `rateLimited(retryAfter)`.
   Services may throw these; they describe an outcome, not HTTP mechanics, and keep
   services free of `Response` objects.

3. **Route wrapper and input helpers** (`src/server/http/route.ts`).
   - `route(handler)` returns a Next.js route handler. It creates a request id
     (`crypto.randomUUID()`), runs `handler`, and converts the result:
     a returned `Response` gets `Cache-Control: no-store` and `X-Request-Id` added; a
     thrown `ApiError` becomes its problem response; anything else is logged with the
     request id (error class and message, as in WS-005) and becomes `internal_error`.
   - `readJson(request, schema)` checks the content type (`415`), parses the JSON (`400`
     if malformed), validates with the Zod schema and returns the typed value, or throws
     `invalidRequest` with one `{ path, message }` per Zod issue. Messages come from Zod;
     the input value is never included.
   - `readQuery(request, schema)` does the same for the query string, and
     `readParams(params, schema)` for path parameters.
   - `json(body, status)` and `noContent()` build success responses.

   An incoming `X-Request-Id` header is ignored: the id is always generated by the server,
   so a client cannot inject text into logs.

4. **Unknown API paths** (`src/app/api/[...path]/route.ts`). A catch-all route handler
   that answers every method with the `404` problem body. Next.js prefers more specific
   routes, so it only receives requests no real endpoint matches.

### Contracts and OpenAPI

`EndpointContract` (`src/lib/openapi/contract.ts`) gains optional `request`
(`{ body?, query?, params? }`, each a Zod schema) and a per-response `problem: true` flag.
`buildOpenApiDocument` then:

- emits request bodies and parameters from those schemas;
- uses `application/problem+json` and `problemSchema` for responses flagged `problem`;
- adds `401` and `403` problem responses to every contract with `public: false`.

The two existing contracts need no change, so the regenerated `docs/api/openapi.json`
differs only by the new `Problem` component if it is referenced; if nothing references it
yet, the file is byte-identical and that is asserted by the existing staleness test.

The health and OpenAPI route handlers are not moved onto `route()` in this item: both are
public, already set their own headers, and health has its own `503` body. They stay
exactly as tested.

### New directory

`src/server/http/` does not exist in the layout of `AGENTS.md` section 3. HTTP helpers
shared by route handlers fit none of the existing folders: they are not domain logic
(`services/`), not authentication (`auth/`), and are server-only so they do not belong in
`lib/`. **This spec proposes adding the line
`http/   Shared route-handler helpers: errors, input parsing, responses` under
`src/server/` in `AGENTS.md`.** That is a change to the constitution and needs the
owner's explicit approval.

## API contract

No endpoint is added or changed. One behaviour changes: a request to a path under `/api/`
that matches no endpoint now returns

```
404 Not Found
Content-Type: application/problem+json
Cache-Control: no-store
X-Request-Id: <uuid>

{ "type": "about:blank", "title": "Not Found", "status": 404,
  "code": "not_found", "detail": "...", "requestId": "<uuid>" }
```

instead of the framework's HTML page. The catch-all is declared **public** by this spec
(`AGENTS.md` hard rule 6): it exposes no data and must answer callers that have no
credentials. It is deliberately absent from the OpenAPI document, since it is the absence
of an endpoint.
