# WS-007 — Playwright end-to-end tests

- Status: Proposed (must be `Approved` by the owner before any code is written)
- Work-item: [WI-007](../work-items/WI-007-e2e.md)
- Canonical docs: `AGENTS.md` sections 3 and 5

## Approach

### Runner and layout

`@playwright/test`, configured in `playwright.config.ts`, with specs in `tests/e2e/` named
`*.spec.ts`. The `.spec.ts` suffix and the separate directory keep them apart from Vitest,
which only looks at `src/**/*.test.ts(x)`.

### The app under test

Playwright's `webServer` option runs `pnpm build && pnpm start` on port 3100 before the
tests and stops the server afterwards. Testing the production build means the tests see
what a real install serves. Port 3100 avoids clashing with a development server on 3000.

Locally an already running server on 3100 is reused; in CI a fresh one is always started.

### A database for end-to-end tests

A third database, `opanel_e2e_test`, created by the Compose init script next to
`opanel_test`. The app under test is started with `DATABASE_URL` pointing at it.

It is separate from `opanel_test` because integration tests empty that database before
every test; sharing it would let a Vitest run wipe data from under a running browser
test. The name ends in `_test`, so the existing guard allows the harness to reset it.

A Playwright global setup applies migrations to it before the server starts, reusing
`runMigrations` from WI-004.

The init script only runs when the data volume is first created, so an existing local
volume needs `docker compose down -v` once. That is documented in the setup instructions
(WI-010).

### Browsers

Chromium only. Firefox and WebKit add install time and CI minutes and are better added
when there is real UI to protect.

### Failure artefacts

Traces and screenshots are kept only for failed tests (`retain-on-failure`), written to
the already ignored `test-results/`. No retries locally; one retry in CI.

### Lint

`eslint-plugin-playwright` is not added now. The existing type-aware rules already catch
the most damaging mistake in Playwright tests (a forgotten `await`).

## Versions

| Package            | Version | Kind |
| ------------------ | ------- | ---- |
| `@playwright/test` | 1.63.0  | dev  |

The latest release is 1.65.0. 1.63.0 is proposed because this development environment
ships with the matching browser build preinstalled, so the tests can be run and verified
here. Upgrading is added to the follow-ups, like Node.js and pnpm.

## Test plan (written first, in this order)

| #   | Level        | Test                                                                                                                            | Covers criterion       |
| --- | ------------ | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 1   | e2e, browser | opening `/` shows a level-1 heading "Opanel" and the page title "Opanel"                                                        | browser test           |
| 2   | e2e, HTTP    | `GET /api/v1/health` returns `200`, `no-store`, and a body that parses with `healthResponseSchema`                              | health                 |
| 3   | e2e, HTTP    | `GET /api/v1/openapi.json` returns `200` and lists `/api/v1/health`                                                             | OpenAPI                |
| 4   | e2e, HTTP    | the app under test is connected to a database whose name ends in `_e2e_test` (checked by global setup before the server starts) | own database           |
| 5   | manual, once | change the expected heading: `pnpm test:e2e` fails and leaves a trace; revert                                                   | gate bites             |
| 6   | manual, once | `pnpm test` runs no `.spec.ts`; `pnpm test:e2e` runs no Vitest files                                                            | runners separated      |
| 7   | manual, once | stop the database: `pnpm test:e2e` fails with the "start it" message                                                            | clear failure          |
| 8   | gate         | `typecheck`, `lint`, `format:check`, `test`, `test:e2e`, `build`                                                                | full five-command gate |

The red step for tests 1 to 3 is running them before `playwright.config.ts` starts a
server (they fail to connect), since the pages and endpoints they exercise already exist.

## Risks and open questions

1. **Playwright 1.63.0 rather than the latest 1.65.0**, for the reason above. **Owner:
   acceptable, with the upgrade as a follow-up?**
2. **Chromium only for now.** **Owner: agree?**
3. **A separate `opanel_e2e_test` database**, at the cost of a one-time
   `docker compose down -v` for anyone with an existing volume (today, only this
   environment). **Owner: agree?**
4. Building before every run makes `pnpm test:e2e` take roughly 10 to 20 seconds longer
   than testing the dev server would. Accepted for fidelity; revisit if it hurts.
