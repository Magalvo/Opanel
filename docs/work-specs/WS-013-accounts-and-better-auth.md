## Approach

1. **Schema** (`src/server/db/schema/`), one Drizzle file per table, exported from
   `index.ts`. TypeScript property names are camelCase, columns snake_case.
2. **Password hashing** (`src/server/auth/password.ts`): `hashPassword` and
   `verifyPassword` over `@node-rs/argon2`, Argon2id, memory 19 456 KiB, 2 iterations,
   parallelism 1 (the OWASP minimum profile). `verifyPassword` catches a malformed hash
   and returns `false`. These are the functions Better Auth is given as
   `emailAndPassword.password.hash` / `verify`.
3. **Password rule** (`src/lib/schemas/auth.ts`): `passwordSchema`, 12 to 128 characters,
   a hand-written message that does not interpolate the value. Better Auth's
   `minPasswordLength` / `maxPasswordLength` are set to the same numbers, from the same
   constants.
4. **Better Auth** (`src/server/auth/auth.ts`): `getAuth()`, a lazily created singleton
   like `getDb()` and `getEnv()`, so importing it never needs the environment. Options:
   `database: drizzleAdapter(getDb(), { provider: "pg", schema })` with the `user`,
   `session` and `account` models mapped to `accounts`, `sessions` and `credentials`
   (`modelName`, `fields`, and `additionalFields` for `kind` and `role`, both
   `input: false`); `emailAndPassword: { enabled: true, disableSignUp: true, hash,
verify, min/max length }`; `session: { expiresIn: 7 days, updateAge: 1 day }`;
   `advanced.database.generateId: "uuid"`; `secret` and `baseURL` from the validated
   env; `telemetry: { enabled: false }`. Its HTTP handler is not mounted (WT-02
   decision 1).
5. **Environment** (`src/server/env.ts`): `BETTER_AUTH_SECRET` (at least 32 characters,
   the name Better Auth reads itself) and `APP_URL` (an `http://` or `https://` URL, the
   app's own origin, used for the origin check of doc 0004 section 7). Both required in
   every environment; `.env.example`, `.env.test`, the E2E environment and the README
   list them. The messages never contain the value.

### Tables

`accounts` (Better Auth `user`)

| Column           | Type          | Notes                                                          |
| ---------------- | ------------- | -------------------------------------------------------------- |
| `id`             | uuid pk       | `gen_random_uuid()`                                            |
| `kind`           | text not null | `human` or `agent` (check), default `human`                    |
| `name`           | text not null |                                                                |
| `email`          | text null     | unique; stored lower-case by Better Auth                       |
| `email_verified` | boolean       | not null, default false; required by Better Auth, always false |
| `image`          | text null     | required by Better Auth's model, unused                        |
| `role`           | text not null | see checks                                                     |
| `disabled_at`    | timestamptz   | null while active                                              |
| `last_seen_at`   | timestamptz   | null                                                           |
| `created_by`     | uuid null     | references `accounts(id)` on delete set null                   |
| `created_at`     | timestamptz   | not null, default `now()`; `updated_at` likewise               |

Checks: a human has an email (`kind <> 'human' or email is not null`); a human has one of
`admin`, `manager`, `member`, `viewer` (`kind <> 'human' or role in (...)`). Agent roles
are not constrained here; WT-05 adds them in its own migration.

`credentials` (Better Auth `account`): `id` uuid pk; `account_id` uuid not null references
`accounts` on delete cascade; `provider_id` text not null (`credential`);
`provider_account_id` text not null; `password_hash` text null; `created_at`,
`updated_at`. Unique `(provider_id, provider_account_id)`. No OAuth token columns (no
OAuth in v1).

`sessions`: `id` uuid pk; `account_id` uuid not null references `accounts` on delete
cascade, indexed; `token` text not null unique; `expires_at` timestamptz not null;
`ip_address`, `user_agent` text null; `created_at`, `updated_at`.

Migration name: `0000_accounts_and_sessions` (generated by `pnpm db:generate`, never
edited after it is applied).

## Risks and open questions

For the owner:

1. **New dependency and a line in the constitution.** `AGENTS.md` section 2 lists no
   password-hashing choice; doc 0001 requires Argon2id and Better Auth's built-in hash is
   scrypt. I propose adding the row `Password hashing | Argon2id via @node-rs/argon2` to
   the table. That is a change to `AGENTS.md`, so it needs your explicit approval.
2. **Hashing parameters.** OWASP minimum profile (19 MiB, 2 iterations, 1 lane). Heavier
   values slow every sign-in and the tests; they can be raised later because each hash
   records its own parameters. Acceptable?
3. **Variable names and requiredness.** `BETTER_AUTH_SECRET` and `APP_URL`, both required
   everywhere including development and tests (the example and test files carry
   non-secret placeholder values). Acceptable, or should `APP_URL` default to
   `http://localhost:3000` in development?

Technical, to be settled by the tests rather than assumed:

4. **Nullable email under Better Auth** (WT-02 risk 2): its model types `email` as
   required. Better Auth only creates and reads human rows, so the column's nullability
   should be invisible to it. Tests 8, 9 and 11 prove it; if not, I stop and report.
5. **Creating the first account in tests.** Sign-up is disabled, so tests create accounts
   through Better Auth's internal adapter if the installed version exposes it, and
   otherwise by inserting rows directly with `hashPassword`. WI-016 and WI-018 will need
   a production way to create accounts; they decide it, this item only needs one for
   tests.
6. **Native module and Next.js.** `@node-rs/argon2` is a native addon. The Next.js 16
   documentation of the installed version decides whether `serverExternalPackages` is
   needed; the production build in the E2E run is the proof.
